## 二、库容表失败细节（最重要的发现）

三轮递进：

1. **2000px（516KB）**：`finish_reason=length`、content 为空——4096 token 全部耗在思维链里（MiMo 是推理模型）。
2. **16k 预算复测**：content 仍为 0，reasoning 17611 字符。思维链尾部暴露**机械编造**：从 868.40m 起以恒定步长（+0.1m / +6.0万m³）无限递推——桃曲坡校核洪水位仅 790.3m、坝顶 792m，868m 纯属虚构。
3. **3000px（969KB）**：HTTP 200，content 10338 字符，但内容仍是**完美等差数列**（每行恒 +0.1m / +6.0万m³，贯穿全线），且水位一路编到 806.6m（超坝顶）。对照人工核验值：768.40m 真值 391.0，mimo 输出 422.0；770.80m 真值 641.0，mimo 输出 566.0；788.50m 应在 3000 万m³ 量级，mimo 输出 1628.0。

判定：对密集数值表格，mimo-v2.5:free 不是"读不准"，而是**不读、直接生成线性插值假数据**——比识别错误更危险，因为格式完美、无法从输出本身察觉。

注：tokenharbor 网关对载荷有 413 上限（原图 5.2MB base64 被拒），无法完全复刻旧管线"原图直发"的口径（旧管线走 openagp 网关无此限制）；3000px 已接近原图（2587×3799 → 2043×3000），且等差数列特征证明模型并未读行。

## 三、工程特性

- **推理模型**：每图先产生 8.9k~17.6k 字符思维链再出正文。简单图可控；密集表会思维链失控（循环/编造），必须在调用侧设大 `max_tokens` 并检查 `finish_reason`——content 可为空。
- 延迟（走代理）：简单图 15~47s；表格 171~174s。免费档单并发，加 3s 间隔未触发限速。
- 输出带 LaTeX 噪声（`\boldsymbol`），入库前需清洗。
- 付费墙：本测试全部走 `:free` 档；qwen3.8-max 等因 balance_zero 未能对比。

## 四、对本项目的建议

1. 密集数值表（库容水位对照表类）：**维持现管线**（离线 VLM + 规程值交叉校验 + 人工 approve），mimo 无增量价值。
2. 图纸/剖面/曲线类（加闸竣工图9、大坝剖面图、泄流曲线）：mimo free 有真实增量（尤其曲线读点，超越旧基线），但**所有关键数值必须交叉校验后人工确认**，其自我声明的"≈"值误差 ±4% 量级。
3. 若要正式替代/补充视觉模型，应充值后在付费档对比 qwen3.8-max / glm-5.3 等的表格识别能力再定。
