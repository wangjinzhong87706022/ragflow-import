## 四、剖面图重试实验（控制变量：同图、同提示词、同网关）

为判断"2 对 2 错（标签错位）"是逐次波动还是系统性误读，用与主跑完全相同的口径重试一次
（网关仍抖：2×300s 超时后第 3 次 6.2s 成功，输出仅 312 字符——输出详略本身也在大幅波动）。

| 运行 | 正常蓄水位 (真值 788.50) | 设计洪水位 (真值 788.54) | 校核洪水位 (真值 790.30) | 死水位 (真值 762.80) |
|---|---|---|---|---|
| 旧基线（08-26，人工通过） | 788.50 ✓ | 788.54 ✓ | 790.30 ✓ | 762.80 ✓ |
| 主跑 | 788.50 ✓ | 790.30 ✗ | 792.02 ✗ | 762.80 ✓ |
| 重试 | 780.50 ✗ | 765.50 ✗ | 790.30 ✓ | 未标注 |

**三次运行三种错误模式，无任何可复现的系统性错误 → 纯逐次感知波动。**

关键观察：**设计洪水位三次读出三个不同值**（788.54 / 790.30 / 765.50），零共识——
因为 788.50 与 788.54 在 1:1500 图上仅差 0.027mm，两条线像素级重叠，只能靠小字引线标签区分，
而原图仅 1280×1858，数字本身难辨认（主跑"792.02"是坝顶 792 与防浪墙 793.2 的融合痕迹；
mimo 也把 788.5 读成 786.5、790.3 读成 790.5——形近数字误读）。

工程含义：
1. 该图上单次 VLM 调用对密集标签栈是"掷骰子"，**多数投票也救不了设计洪水位**（三次零共识）；
   正常/校核/死水位 2/3 多数可投票收敛，设计洪水位不可。
2. 可靠路径只有两条：**用已人工通过的 out/vision/ 基线**（现行做法），或**提高扫描分辨率**重制该图。
3. 交叉校验（`TEXTUALIZED_VALUES`）+ 人工 gate 对此类图不可省——本次波动实证。

## 五、结论

1. **已入库的 `out/vision/` 基线依然成立，无需重做。** 量化 Qwen 能复现自己的人工通过
   结果（库容表逐锚点一致），但剖面图本次反而退步（4 对 → 2 对 2 错），说明同模型逐次
   调用有波动——`TEXTUALIZED_VALUES` 交叉校验 + 人工 gate 不可省。
2. **mimo 与 Qwen 互补**：表格类必须用 Qwen（mimo 会静默幻觉且格式完美、极具迷惑性）；
   曲线类 mimo 反而能取点。若要提升 06-泄流曲线 入库质量，方向是改提示词
   （明确要求"沿曲线读取关键点"）或双模型互补，而非换模型。
3. **openagp 网关不满足生产可用性**：间歇 0 字节挂起 + 503，同一时段内逐图成败随机。
   接入 `vision_extract.py` 前需补自动重试与降级路径。
4. 量化 Qwen 无 MiMo 的推理耗尽问题（本次四图 finish_reason 均为 stop，无 content 为空）。
