## 一、背景与任务

F1（BIFF 表垃圾块）经 P1 试点否决 table 法、选项 B 完成三份最高价值壳迁移（洪水统计(1)/较大洪水统计表/2011年下泄，140→28 块）后，ds3 仍余 20 份表格保持 naive 原状。本轮收口要回答三个问题：

1. 剩余 20 份各自该 **keep / fuse / ignore**（分优先级）；
2. `洪水过程_dup.xls`（语料扫描期因 `_dup` 命名被去重排除）是否值得入库；
3. ds4 三份台账 xlsx 是否需要处置。

调查方法：**线上 chunk 抽样定"病情"**（每份前 2 块，20/20 全覆盖）+ **calamine 离线读数定"内容"**（sheet 级 shape+标题行，24 文件）+ import_state 对齐 KB 名与语料路径（RAGFlow 上传同名自动加 (1)(2)(3) 后缀，KB 名不可反推语料路径）。

## 二、核心发现

### 2.1 病情定性：F1 是格式病，不是个案病（本轮最重要结论）

| 族 | 文档数 | 块数 | 抽样垃圾率 |
|---|---|---|---|
| BIFF `.xls`（openpyxl 失败→pandas 降级，`Unnamed:`/`nan`/`——Data` 指纹） | 17（ds3） | **789** | **17/17 全部 100%** |
| 真 `.xlsx`（openpyxl 正常路径，`表头: 值; None：值` 形状） | 3（ds3）+3（ds4） | 8+97 | **0/6** |

即：**凡 .xls 必垃圾、凡 .xlsx 必干净**，与表本身好坏无关。处置对象就是 17 份 .xls 族；
xlsx 一份都不用动（ds4 评估结论随之确定）。另有轻症变体：`2001年洪水过程线.xls` 呈
`日期：nan; 报汛时间：…; 流量：…` 形状——值可读但合并单元格的日期前向填充断裂，日期上下文丢失。

### 2.2 dup 不是复件，是在库文件的全集（裁定依据）

| sheet | 在库 10-3/洪水过程.xls | **dup** | 说明 |
|---|---|---|---|
| 下泄水量 | 56 行 | **72 行** | dup 为超集 |
| 岔口弃水 | 99 行 | **167 行** | dup 为超集 |
| 入库洪水 | 无 | **68 行**（10月3日-7日柳林断面） | dup 独有 |
| 桃库溢洪道溢流 | 无 | **28 行（2021 年 11 月，788.75→789.08）** | **全库唯一溢洪道溢流过程记录** |
| 降雨量 | 无 | **「10.3」洪水预报值：面雨量 120.68 / 净雨深 24.14 / 洪量 W=2003.2 万m³** | dup 独有 |

即入库的 10-3 洪水过程.xls 是残缺版。建议：dup 三个独有 sheet 并入 10-3 融合文本（一份文档全覆盖），dup 本身不入库（`_dup` 命名本就被 corpus.py 去重，壳路径不走 corpus 扫描，零冲突）。

### 2.3 内容级新发现（超出 triage 本身）

1. **水位库容曲线推求.xls（523 块，F1 之最）实为曲线推求工作簿**，12 sheet 混装三个时段：
   `070729`（**2007**-7-29）洪水过程线 ×2、**2008 年水文要素年表**+柳林 2008 来水量（396 行）、
   逆时序推求水位库容曲线、**水位库容查对表 ×2（766.6→792 全幅，298 行×24 列 + 273 行）**。
   查对表是 ds2 库容曲线壳的数据母本——彻底解既不该是全量 fuse（239 行 QA 轰炸教训），
   也不必是放任 523 块垃圾，"局部 fuse（查对表整十位锚点+插值规则）"列为选项。
2. **TB0207.xls 元数据 `year=207`**：阶段0 年份正则从文件名 "TB0207" 抓出 207 直注入 KB；
   表内铁证 `35765=1997-12-01`，应改 1997。就地 PATCH document 可修，分钟级。
3. **2001年洪水过程线.xls `year=2001`**：按文件名归档与按内容归档（实为 2010-7-24，错误②）矛盾，
   KB 名不动的前提下 year 改不改交用户裁（D7）。
4. **新存疑④（已补入档案反馈 存疑②）**：`06-2008年洪水(8-22)/降雨量统计.xls` 内容为
   「**7月2日--9日**流域各雨量站日降雨量统计表」+「枢纽全年累计降雨215.5毫米」——与目录场次
   8-21 不符（8·21 的降雨链在洪水统计.xls 内）。P1-5 给它 patch 的 `2018-8` 系**目录归因**而非
   内容归因，离线无法定年，待档案方核实后再纠。
5. **场次枚举缺口**：`flood_event` 枚举无 `2010-7`/`2010-8`/`2011-7`。2010 三份与错误③
   （洪水过程(3).xls 实为 2011-7-29）若按真实场次归因需扩枚举（P1-5 同款机械：config.py +
   tag_vocab + ds0 标签库 + patch，约 +1h，不影响 Q5 既有过滤语义）；或统一归 `其他` 免扩。
6. **2011 年 7 月场次全库无覆盖**：已壳的 2011年下泄水量统计.xls 只覆盖 110905/110911/110918
   九十月场次；错误③文件恰是 2011-7-29 完整链（入库/下泄/降雨 3 sheet）——fuse 它有独立史料价值。

## 四、处置方案与决策清单

处置动作全部复用既有机制（**零新代码**）：fuse = `src/shell_import.py` 壳模式（删旧→重传原 xls
UNSTART→patch 元数据→挂融合切片，preflight 锚点门 + FAIL 即停 + 回滚存档先行）；meta-patch =
就地 PATCH document + doc_meta 同步。内容成本 = calamine 读数（extract_xls.py 通道现成）+
人工校对 + 5 段式融合文本 + 切片 + 探针验证，无 LLM 调用。

| # | 决策 | 建议 | 成本 |
|---|---|---|---|
| D1 | S 级 5 份 fuse（批次一） | ★批准 | 场次链 1–2h/份 |
| D2 | 2010 三份 fuse（批次二，#6+#8 合并）；含枚举扩否 | ★批准 | 3–4h（+枚举 1h） |
| D3 | 小表 fuse（防洪减灾统计表） | ★批准 | 0.5h/份 |
| D4 | 洪水过程(3).xls（2011-7-29 错放） | ★fuse+扩枚举 2011-7 | 1–1.5h |
| D5 | dup 处置 | ★独有 sheet 并入 10-3 融合文本，dup 不入库 | +0.5h |
| D6 | 水位库容曲线推求.xls（523 块） | ★局部 fuse（查对表整十位锚点+插值规则，不做逐行 QA） | 3–4h |
| D7 | 就地元数据小修（TB0207 year→1997；2001 过程线 year→2010 与否） | ★批准 | 分钟级 |
| D8 | 降雨量统计(1).xls 存疑 | ★已补入档案反馈，待档案方核实 | 0（已完成） |

**若全批**：批次一（D1+D5）→ 二（D2+D7）→ 三（D3+D4）→ 四（D6），严格串行、逐份 preflight+
探针门，每批后跑 xls 12 题 + QC 六问 + 26 题回归。合计融合文本 10–11 份，789 垃圾块 →
~120–160 结构化块（ds3 收敛 ~25%），人时 ≈ **13–19h**。**只批 S 级 ≈ 6–9h**，即可覆盖
F1 主要病灶（场次链）的 80%。
