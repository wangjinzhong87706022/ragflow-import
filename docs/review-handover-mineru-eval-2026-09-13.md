## 4. 方法学评审（问题 → 处置）

### 4.1 用例措辞与已知故障同源（P0，已修复）
交接文档已诊断"图片问题带页码 → Agentic 关键词过滤丢命中"，但 135 条用例里 **30/30 条图片用例
仍全部带页码**、8 条公式用例带页码——即待办#2（修措辞复测）所需的前置修改根本没做。
**处置（已落地）**：30 条图片用例去页码；8 条无图号者改内容锚定（"1—捣棒；2—试模；3—玻璃板"
式部件编号）；公式 8 条保留页码（公式用例页码是"第 1 页出现公式 X"的出处说明，且该类首批全过，
不构成故障面，留待全量结果验证）。
**复测（API 通道实测）**：TC-001 ❌→✅（命中图号+完整要素描述）；TC-092 ❌→✅（5/5 关键词）；
TC-022 仍 ❌（"知识库中未找到"）→ 定性为图号未进索引关键词，`important_keywords` PATCH 是
唯一 API 级解法，已提升为待办#2。

### 4.2 表号串扰只提了方案未落用例（P0，已修复）
TC-071 两次答案对到不同表（D.0.1-1 vs D.0.1-3），文档给的方案①是写 `important_keywords`、
③是"提问带完整表号与表名"，但用例没改。
**处置（已落地）**：13 条 D.0.1-1/D.0.16/D.0.17 问题全部补表名（项目特性表/工程量汇总表/
工程施工总进度表）。`important_keywords` 仍是待办（需对比实验证明增益）。

### 4.3 单次结果当结论，缺稳定性维度（P1，建议采纳）
TC-092 首批 ❌、本次复测**同一问题原文未改**就 ✅——证明 Agentic 过滤有抖动，单次 pass/fail
不可作为结论。交接文档 §4 的"定性结论"未标注这一点。
**处置（已写入待办#3）**：全量报告对每类抽 ≥3 条复跑 2 次，报"稳定通过/抖动/稳定失败"三态。

### 4.4 判分函数缺陷（P1，已修复）
- TC-031 关键词 `["(20","2","℃"]`——`"2"` 单字符，任何含数字的答案必命中；80 条用例存在
  ≤2 字符关键词（"100"、"30"、"5"……纯数字串在工程答案里极易假阳）。
- 关键词未 strip，`" 和 "` 这类首尾带空格的关键词在 includes 匹配下形同虚设。
**处置（已修复）**：两个运行器判分统一 strip；**阈值维持 ≥50% 且 ≥1 命中不变**（改阈值会让
历史结果不可比），但强烈建议全量报告增加"人工复核 MISS 全部 + PASS 抽检 20%"环节（已写入待办#5）。
**遗留（未改，需用户决策）**：80 条短关键词用例的 `expected_keywords` 本身建议重写为
带上下文的复合关键词（如 `"100~30%"` 而非 `"100","30"`）——改动会影响与首批 11 条的可比性，
留给接手 Agent 在全量跑之前批量处理。

### 4.5 反幻觉用例答案错位（P1，建议修）
- TC-128"闸门数量 5 台的抽样比例"：表 2.3.4 的 1~10 档真实存在（100~30%），关键词也是
  `["100","30"]`——这是**正常数值题**被放进反幻觉类，会把"答出真值"记成反幻觉 PASS。
- TC-124 关键词 `["模板","无数据","按实际","填写"]`：助手系统提示明确要求答"需按实际工程填写"，
  关键词与提示词强耦合——测的是"助手遵循提示"还是"RAG 不编造"？需在报告里分开归因。
**处置（未改用例）**：已在交接文档待办注明；建议 TC-128 移入"表格"类或删除，TC-124 类注明
"提示词遵循"维度。改 JSON 会动 135 条基线，交由接手 Agent 与用户确认。

### 4.6 v2 运行器全量场景缺陷（P0，已升级 v3）
1. **会话堆积**：每题 New conversation 只新建不删，135 条残留 135+ 会话（实例上已观察到
   首批遗留 11 个）。→ v3：API 运行器每 10 题批量 DELETE；浏览器运行器每 10 题页面内
   fetch 清理（保留当前）。
2. **无断点续跑**：中断即全量重跑（4~5 小时窗口很脆）。→ v3：两运行器按 OUT_FILE 已有
   ID 跳过，逐题增量落盘（进程被杀也只丢当前题）。
3. **SSE 单通道**：漏捕即 `[EMPTY_ANSWER]` 误判。→ v3：DOM 兜底 + 超时空答案自动重试 1 次
   （新会话重问）。
4. API 运行器无错误分类。→ v3：`[ERROR]`（业务 code≠0，如 rerank 故障复发）与
   `[EXC]`（网络）分前缀，汇总时区分"服务故障"与"检索不到"。

### 4.7 API 运行器定位建议（P2，已调整文档）
交接文档把浏览器运行器当主力（"全量 135 条浏览器实测"）。实测 API 通道答案完整（含
引用标记），且无需 Playwright 环境、天然抗 UI 改版。**建议**：API 为主力跑全量，
浏览器用于抽检取证与引用展示验证（图片引用显示只有浏览器能验）。已更新交接文档待办#1。
