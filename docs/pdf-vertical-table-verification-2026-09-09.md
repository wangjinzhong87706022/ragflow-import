## 3. 修复实施

- 端点：`PATCH /api/v1/datasets/{ds}/documents/{doc}/chunks/{chunk_id}`（body `{"content": ...}`）。经本地仓库 `api/apps/restful_apis/chunk_api.py` 证实：服务端重新分词并**重新向量化**后写回 doc store，检索即时生效，无需重新解析文档。
- 删除：`DELETE /datasets/{ds}/documents/{doc}/chunks`，body `{"chunk_ids": [...]}`。
- 修复前全量 chunk 备份：`chunks_backup_before_fix.json`；修复后快照：`chunks_after_fix.json`。
- 修复后状态：**123 chunks**（127-4），`农林牧油/经渍林/微地坝/修田` 等误读串全文检索为 0。

## 7. 经验沉淀（增量）

1. **chunk 级修复优于重新解析**：PATCH content 会重分词+重嵌入并即时生效；28 处缺陷修复全程未触发 30 分钟的重新解析。
2. **扫描件 VLM 表格重建的"干净变体"也可能整列丢失**（D.0.5 缺省列、D.0.20 缺渠道/种草列、D.0.10 缺一个坡度级），评审必须逐列对照原表，不能只看"表结构完整"的直觉。
3. **第一轮的两类误报**：`<br>` 标签被计为 OCR 损坏（"<"计数）；"13 列全对"未发现缺省列。逐列放大核对是唯一可靠手段。
4. **判分脚本要先剥离 markdown 符号再匹配**，否则加粗答案会误判 FAIL。
